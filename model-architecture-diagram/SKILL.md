# 模型结构分析与绘图

把指定模型的真实计算路径转化为可读、可追溯的架构图。默认使用中文说明、英文模块名与数学符号；用户指定语言、版式和文件格式时优先遵从。

## 确定对象并分析输入

支持本地文件/目录、仓库 URL（含子路径、分支或 commit）、配置、论文/报告 PDF 或链接，以及组合输入。仓库根路径可先静态检索，无须用户逐一指定文件。记录 commit、模型变体、有效配置、训练/推理模式；仅在缺失信息会改变架构且无法从输入判断时询问。只有报告时照样工作，注明“报告级架构”，不可虚构实现路径。

先读取 [references/analyze-model.md](references/analyze-model.md)，定位入口类、配置与 `forward`，沿实际调用顺序分析。不要从目录树、类名或参数总量直接推断计算图，不要为绘图下载权重或启动训练。优先静态阅读，避免为分析而导入陌生仓库。

## 建立可核查的结构

先写 `<model>_analysis.md`，包含：

- 模型标识、版本/commit、选定配置、图的抽象层级和模式。
- 输入到输出的计算链、重复层及分段规则、核心分支、残差、路由、融合、缓存与状态。
- 关键参数表和必要张量形状；区分总专家/激活专家、总参数/激活参数。
- 证据表：`图中节点或边 ID | 结论 | 来源文件:行号/报告页码 | 已确认/推导/未知`。
- 代码与报告的差异，以及无法确定的信息。图中不要把推测画成确定事实。

代码图以选定版本的实现和配置为准；论文概念图以选定报告为准。两者有差异时说明，不拼成一个未存在的模型。符号尺寸和条件分支可以保留；无法证实的数值省略或标注未知。

## 选择视图并编排

绘制前读取 [references/infratech-style.md](references/infratech-style.md)。其中区分参考图片的观察与本技能新增约定，包含样本、配色、布局、连线及文字规则。

默认交付一张“整体骨架 + 核心模块展开”的高分辨率总图。保持主干清晰，关键机制展开到算子或子模块层级。复杂架构可拆成整体、Attention、FFN/MoE、多模态前端等分图，并在总图标注对应关系；不要规定每个模型必须有相同数量的面板。

- 按真实数据流确定方向；InfraTech 式纵向主干优先采用自下而上，并用箭头消除歧义。
- 重复层用容器、层索引与 `×N` 表示；分段或交替层明确范围/周期，不把首层 Dense 与后续 MoE 折叠成同一种层。
- 残差旁路明确绕过哪些算子并落到加法节点；乘法、拼接、加权和、选择/路由使用不同标签。
- 一种视觉语义贯穿全图；放大关系、真实数据流、缓存读写和可选路径明确区分。
- 模块、模态、层安排来自当前证据；不要因为参考图含 MLA/MoE 就为普通模型添加这些结构。

## 生成可编辑图和图片

默认用确定性矢量绘图（SVG、draw.io 或可复现的绘图代码），保证文字、公式与连线能逐项修改。可用本技能提供的标准库 SVG 渲染器：

```bash
python scripts/render_diagram.py assets/example.architecture.json --output <输出目录>/example.svg
```

实际使用时先复制模板到工作目录，按已分析的模型重写节点、边、面板、尺寸、文字和 `evidence`，再渲染。模板是标明为教学示例的小型网络，不是任何真实模型的事实来源。格式和图片导出见 [references/diagram-format.md](references/diagram-format.md)。脚本提供自由坐标和基础组件，不替代模型分析，也不保证自动布局无冲突。复杂矩阵/张量图可扩展 SVG 或另写局部绘图代码。

同时导出 PNG（推荐长边至少 2400 px，优先无损；保持可读字号），需要时附 JPG/PDF。可使用环境已有的 SVG 光栅化工具，不假定特定系统路径或商业应用存在。只有 SVG 而未生成实际图片时不能声称图片交付完成。图像生成工具可用于无语义装饰；模块名、公式和连接关系应由可控的矢量/代码层绘制。

## 校验并交付

语义复核：逐条对照证据表，检查执行顺序、层数、Norm 位置、残差端点、头维度、RoPE 作用对象、MoE 路由与聚合、模态融合、缓存/状态读写。不要把训练专属辅助头放进默认推理主干。

实际渲染并查看总图和局部：检查文字裁切、溢出、遮挡、错字、公式、箭头方向、交叉线及面板边界。整体缩放后主干可辨，局部放大后标签可读。拥挤时增加画布或拆图，避免只缩小字体。脚本通过只代表格式有效，不代表视觉和语义正确。

默认交付：

- `<model>_architecture.png`：可直接使用的结构图片。
- `<model>_architecture.svg`（或用户指定的可编辑格式）。
- 可复现的图描述 JSON/绘图源代码。
- `<model>_analysis.md`：结构说明、证据索引、来源与剩余不确定性。

分析文件注明风格参考 `CalvinXKY/InfraTech/models` 与参考 commit；图上可放短来源说明，避免挤满长 URL。不要复制上游图片、作者标识或二维码来冒充新图。交付时展示图片或可访问的预览，简要说明所选模型变体与证据限制。
