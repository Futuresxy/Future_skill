## 从图片观察到的共性

### 1. 先骨架，再展开

白底、高密度信息、顶部居中粗体标题“模型名（总参数/激活参数）”，附近给高清图来源。主数据流通常自下而上；输入 Text/VisionData 在底部，Tokenizer/Embedding 或 PatchEmbed 在入口，最终 Norm/LM-Head 在顶部。主干置左或居中，关键机制展开在空白较多的一侧。

整体图里的 Attention/MLP/MoE 常用彩色文字的空心虚线框；同色虚线从框边缘引到展开面板边缘，构成“放大”关系。展开线不是数据流，没有数据箭头。主干仍保留模块位置、Norm 和残差，不能被细节图取代。

### 2. 用几何承载计算语义

- 实心圆角矩形表示操作/模块，如 RMSNorm、Linear、Router、SiLU。
- Linear 升/降维在部分图里用梯形强调维度变化；形状是辅助，仍需写投影名和维度。
- 圆形加号是残差或分支求和，圆形乘号是逐元素门控/乘法；Cat、Split 有明确文字。
- 大虚线容器圈住重复 block 或模块范围，旁边标 `×N`；多种层使用嵌套容器，不把不同结构压成同一种 block。
- 专家采用少量代表框加省略号，并注明总数、每 token 的激活数和 Shared 分支；不画几百个框。
- 多模态 token 以并排小色块表达序列构成，编码器输出到语言模型的融合位置有实际连线。

### 3. 按语义着色，但不是全仓库唯一色表

观察到常用橙色 Attention、绿色 FFN、蓝色 MoE 标题/Router/残差、红色 cache/重要参数、紫色细化的 scaled dot-product 子图。Kimi K2 主干偏深灰、MiniMax 主干偏珊瑚红、DeepSeek 主干偏紫蓝，较新图有蓝色渐变。Qwen3.5 的 DeltaNet 使用绿色，会与别的模型中 FFN 的绿色角色不同。

因此每张图先定义自己的颜色图例，模块族内部保持一致。不能宣称“绿色永远只能代表 FFN”，也不要照搬上游渐变和低对比水印来降低可读性。

### 4. 连线和标注是内容主体

黑色细实线加箭头表示确定的数据流；正交折线保留残差和旁路，尽量不穿过文字。形状 `[seq_len, heads, head_dim]` 等紧贴相关边；投影矩阵 `W [in, out]`、RoPE 维度、head 数、expert 数等写在对应子图附近。Q/K/V 标签常用红字。cache 用红色小矩形，读写连接明确。

图片里虚线还用于专家路由等计算含义，不仅仅表示放大。因此新图应加图例，把“选择路由”和“无箭头展开引线”区分；不能通过虚线外观猜测含义。原图极高像素尺寸说明它们面向局部放大阅读，缩成聊天小图时细节会消失。

## 本技能采用的制作约定（新增，不冒称上游规定）

### 推荐视觉 token

下表是接近观察风格的可维护近似值，不是从原图恢复出的精确色号。根据目标模块族覆盖颜色，并同步图例。

| role | 建议色 | 用法 |
| --- | --- | --- |
| backbone | `#2997EC` | Embedding、Norm、Head、主干操作 |
| attention | `#FF9E10` | Attention、Q/K/V、RoPE 的模块族 |
| ffn | `#91CC46` | FFN/MLP 与门控分支 |
| moe | `#537DFA` | MoE 标题、Router、专家容器 |
| vision | `#FF7777` | 视觉 Merge/跨模态融合 |
| detail | `#8035A5` | 子模块进一步细化，如 SDPA |
| cache | `#ED232A` | KV/cache 或显著状态，必须标明含义 |
| neutral | `#444444` | 中性分组、注释或不需强调的模块 |

白色背景，正文深灰/黑。亮色填充上的正文可改深色，优先对比度；不把颜色作为唯一语义。可用纯色替代渐变，减少导出兼容问题。

### 推荐版式参数

以 `1600×1800` 逻辑坐标为普通多面板图的起点，复杂 VLM/混合模型增加高度或拆图。外边距约 48–72，面板间距 32–64，节点高约 38–56，连续算子净间隔至少 24，主干占宽约 25%–35%。这是起点，不能覆盖实际内容需求。

标题 30–40、面板标题 20–26、模块标签 16–20、形状/注释 14–17 逻辑像素。线宽约 1.4–2，虚线容器 `8 5`；形状标签在空白通道中，不骑在线上。中文使用可用的 CJK 无衬线字体。长公式手动换行或扩展框宽；不要用缩字号掩盖排版问题。

总图只保留会改变读者理解的尺寸和超参数；庞大配置表放分析文件。复杂注意力机制分别解释数学计算流和实现优化流；矩阵吸收、kernel fusion、缓存复用不能混画成重复计算。

### 建议的连线图例

| 线型 | 含义 |
| --- | --- |
| 深色实线单箭头 | 已确认的数据流；残差也用实线并明确 Add 端点 |
| 彩色虚线、无箭头 | 模块到细节面板的展开关系，不是运算 |
| 虚线箭头 + “top-k/selected”文字 | 选择路由或可选计算；必须以文字解释具体含义 |
| 红色实线箭头 + read/write | cache/状态访问；颜色可依图例改变 |

对未确认结构优先省略细节并加“未公开/未知”；需要示意假设时用明确文字“推断”或“示意”，不能与已确认分支混同。训练专属 MTP/loss 使用独立虚线容器并写明模式，不能仅因为参考样本顶部有 MTP 就在所有模型中添加。

## 视觉验收

沿箭头从输入走到输出，再沿主干模块到展开面板逐一核对。检查：重复计数能否还原配置、Add/Multiply 是否混用、专家是否经过正确聚合、缓存读写是否可区分、红色高亮是否有明确意义、形状是否属于正确的边。最后看 100% 局部与缩放总览，确认文字、箭头和分组线没有互相遮挡。
